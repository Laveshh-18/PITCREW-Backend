# Backend (Nikhil): Road-Repair Prioritizer

FastAPI + Supabase Postgres/PostGIS. Implements `backend/app/` and `backend/db/` from CONSTITUTION v1.1.0.
`backend/core/` is a **working reference implementation of Lavesh's pure-Python package** so everything runs end to end today.
Lavesh can replace files in `core/` freely as long as the function signatures in Constitution Section 7 stay the same.

```
backend/
  app/            main.py, config.py, security.py, db.py, photo.py, exif.py, storage.py, seed.py
    routers/      system, refdata, potholes, complaints, sensors, planning, admin
    repositories/ SQL only (geo_sql.py is the only place lat/lng become PostGIS x,y)
    services/     ingest.py = locked fusion transaction (9.4)
  core/           scoring, fusion, priority, scheduler, FCFS, compare, verification (pure Python)
  db/migrations/  001_init.sql  (schema + RLS + Realtime)
  fixtures/       synthetic demo data (generated by tools/make_fixtures.py)
  tests/          core/ (no DB), api/ (no DB)
  tools/          make_fixtures.py
```

## 1. Run locally
```bash
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                    # then fill it in (see section 2)
uvicorn app.main:app --reload
```
Open http://127.0.0.1:8000/docs (development only; disabled when `APP_ENV=production`).

Tests (no database needed): `pytest`

## 2. Environment (.env, never committed)
Generate the two keys: `python -c "import secrets; print(secrets.token_urlsafe(32))"` (run twice).
`DATABASE_URL` = Supabase **Transaction pooler** string (port 6543). In production the app refuses to start if
`ADMIN_API_KEY` or `SENSOR_API_KEY` is shorter than 32 characters.

## 3. Database
Run `db/migrations/001_init.sql` once in the Supabase SQL editor (it already contains the 1.1.0 changes:
photo verification columns, `crew_secrets`, RLS, Realtime). Create the Storage bucket `complaint-photos`
(public read, `image/jpeg` only, 5 MB).

## 4. Seed the demo data
```bash
python tools/make_fixtures.py        # only if you want to regenerate fixtures/
curl -X POST "http://127.0.0.1:8000/v1/admin/seed?reset=true" -H "X-Admin-Key: $ADMIN_API_KEY"
```
The response contains `crew_keys`. **They are shown once.** Save them in a password manager.
Lost one? `POST /v1/admin/crews/crew-a/rotate-key`.
Seed photo badges point at `sample-1.jpg ... sample-8.jpg` in the bucket: upload any 8 small JPEGs under those names.

## 5. Deploy on Render
- Root Directory: `backend`
- Build: `pip install -r requirements.txt`
- Start: `uvicorn app.main:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips='*'`
- Health Check Path: `/health`
- Env vars: everything in `.env.example` with `APP_ENV=production`. Do not set `PORT`.

## 6. Endpoint cheat sheet
| Who | Header | Endpoints |
|---|---|---|
| public | none | GET everything, `POST /v1/complaints`, `POST /v1/plan` |
| sensor | `X-Sensor-Key` | `POST /v1/sensor-events`, `/batch` |
| crew | `X-Crew-Key` | `POST /v1/potholes/{id}/fix` |
| admin | `X-Admin-Key` | `/v1/admin/*`, `PATCH /v1/crews/{id}`, full (non-public) response shapes |

## 7. Known deviations and honest notes
- **Photo hash** is computed on the oriented, resized JPEG instead of the original (a 9x8 dHash is size-invariant).
- **Rate limits and the auth-failure block are in memory**: correct for the single free-tier worker, reset on restart.
- **5 MB limit**: oversized bodies are refused up front via `Content-Length`, and the upload is also counted chunk by chunk.
- **Queue/plan caching (15.5)** is not implemented yet; add it only if k6 shows you need it.
- `GET /v1/queue` and `POST /v1/plan` ignore `is_test` rows.
- Fixtures live in `backend/fixtures/` because Render only deploys the `backend` folder. Keep them in sync with `contracts/fixtures/`.
- Not yet written (next steps): `scripts/test_rls.sh`, `scripts/smoke.sh`, `loadtests/*.js`, `check_contract.py`, DB-backed API tests.
- This code was syntax-checked and its core logic and photo pipeline were tested, but the server was **not run against a live Supabase** yet. Expect to fix small things on first contact.
